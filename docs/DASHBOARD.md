# Данные для дашборда

Всё, что нужно, чтобы построить свой интерфейс поверх прайс-листов Kaspi.
Ничего запрашивать у меня не надо — источники открыты и отдают CORS.

## 1. Источники

| Что | URL | CORS | Обновление |
|---|---|---|---|
| Прайс Centersna (матрасы + архив) | `https://r1kse.github.io/kaspi-xml/centersna.xml` | `*` | каждые 30 мин |
| Прайс Matras.kz (кровати и прочее) | `https://r1kse.github.io/kaspi-xml/matras.xml` | `*` | каждые 30 мин |
| Метка сборки | `https://r1kse.github.io/kaspi-xml/built-at.txt` | `*` | там же |
| Фид 1С (остатки по всем складам) | `https://centermatrasov.kz/kspmat/kaspi_catalog.xml` | **нет** | см. «Дефекты» |

Наши файлы отдаются с `Cache-Control: max-age=600` — CDN держит их до 10 минут,
плюс расписание GitHub опаздывает на 5–20 минут. Реальная свежесть данных на
дашборде: до ~45 минут. Есть `ETag` и `Last-Modified` — на них можно делать
условные запросы.

**Фид 1С из браузера не забрать**: сервер не отдаёт `Access-Control-Allow-Origin`.
Нужен либо серверный прокси на твоей стороне, либо забирать его в фоне и
складывать себе. Из нашей сборки он тянется на раннере GitHub, там CORS не при чём.

## 2. Формат XML

Один и тот же для обоих файлов.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<kaspi_catalog date="2026-09-02 10:38" xmlns="kaspiShopping">
  <company>Centersna</company>
  <merchantid>Centersna</merchantid>
  <offers>
    <offer sku="N04353180200">
      <model>Матрас ортопедический "НАНОТЕКС МОНО" (средне-мягкий) Размер 1,80*2,00</model>
      <brand>centr-pravil-nogo-sna</brand>
      <availabilities>
        <availability available="yes" storeId="Centersna_PP1" stockCount="3"/>
      </availabilities>
      <cityprices>
        <cityprice cityId="750000000">257850</cityprice>
      </cityprices>
    </offer>
  </offers>
</kaspi_catalog>
```

Поля:

| Поле | Смысл |
|---|---|
| `date` | когда собран файл, время Алматы (UTC+5), формат `YYYY-MM-DD HH:mm` |
| `merchantid` | кабинет: `Centersna` или `30378397` |
| `sku` | артикул. **Разный в двух файлах**, см. раздел 4 |
| `model` | название с размером в конце: `Размер 1,80*2,00` |
| `available` | `yes` / `no` — продаётся ли |
| `storeId` | склад, см. раздел 5 |
| `stockCount` | остаток; при `available="no"` всегда `0` |
| `cityId` | город Kaspi; `750000000` = Алматы |
| `cityprice` | цена продажи в тенге, целое число |

Пространство имён `kaspiShopping` — при разборе через DOMParser учитывай
namespace либо ходи по `getElementsByTagName` без него.

Парсинг в браузере:

```js
const res = await fetch("https://r1kse.github.io/kaspi-xml/centersna.xml");
const doc = new DOMParser().parseFromString(await res.text(), "application/xml");
const offers = [...doc.getElementsByTagName("offer")].map((el) => {
  const av = [...el.getElementsByTagName("availability")];
  return {
    sku: el.getAttribute("sku"),
    name: el.getElementsByTagName("model")[0]?.textContent.trim(),
    brand: el.getElementsByTagName("brand")[0]?.textContent.trim(),
    price: Number(el.getElementsByTagName("cityprice")[0]?.textContent),
    stock: av.reduce((sum, a) => sum + Number(a.getAttribute("stockCount") || 0), 0),
    inStock: av.some((a) => a.getAttribute("available") === "yes"),
    stores: av.map((a) => a.getAttribute("storeId"))
  };
});
```

## 3. Что означают числа

**Файл — снимок целиком, а не изменения.** В нём всегда весь ассортимент
кабинета. Товар снимают с продажи не удалением строки, а `available="no"` +
`stockCount="0"`. Если оффер исчез из файла — Kaspi считает, что о нём просто
не сообщили, и старое состояние остаётся висеть. Поэтому пустой или обрезанный
файл опаснее, чем несобравшийся: он снимет с продажи всё.

Текущие числа по `centersna.xml` (меняются, это ориентир):

- 535 офферов = 125 живых из фида 1С + 410 архивных;
- 46 в наличии — остальные `available="no"`, потому что на складе-источнике ноль;
- 186 позиций с ценой из таблицы (125 живых + 61 архивная), у остальных
  архивных цена та, что была в кабинете.

По `matras.xml`: 226 офферов, все с ценой из таблицы.

## 4. Артикулы — три разные нумерации

Не сравнивай артикулы между источниками напрямую, они из разных систем:

| Где | Вид | Пример |
|---|---|---|
| Фид 1С и таблица цен | 10 цифр, ведущий ноль значим | `0339200200` |
| Кабинет Centersna | `N` + цифры, либо 12 цифр | `N04353180200`, `301358180200` |
| Кабинет 30378397 | те же, что в 1С | `0339200200` |

В `centersna.xml` уезжает артикул Centersna, если он известен, иначе артикул 1С.
Известен он для 45 позиций из 125 — их подтягиваем из архива кабинета по
совпадению названия и размера. То есть **у ~80 живых матрасов в файле пока стоит
артикул 1С**, и Kaspi такой артикул не знает. Чинится выгрузкой активных товаров
из кабинета Centersna — её пока нет.

Ведущие нули: `0339200200` в Google-таблице легко превращается в число
`339200200`. При сверке сравнивай ещё и «только цифры без ведущих нулей».

Сопоставление по названию, если понадобится: приводим к нижнему регистру,
`ё`→`е`, выкидываем `матрас`, `ортопедический`, `HS`, `Размер`, кавычки и скобки,
схлопываем пробелы, отдельно вытаскиваем размер вида `1,80*2,00`. Ключ =
«название без размера» + «размер». Готовая функция — `nameKey` в `src/merge.mjs`.

## 5. Склады — две нумерации с одинаковыми именами

**Главная ловушка.** Обе называются `PP<номер>` и означают разное.

| Нумерация | Где встречается | Пример расхождения |
|---|---|---|
| кабинет **30378397** | `storeId` в фиде 1С | `PP7` = Атырау |
| кабинет **Centersna** | `Centersna_PP*` в `centersna.xml` | `Centersna_PP7` = Кызылорда |

Полные справочники с адресами — `src/stores.mjs`, экспорты `FEED_STORES`
(71 склад) и `CENTERSNA_STORES` (10 складов). Импортируй оттуда, не переписывай.

Связь между системами — только по адресу: 1С `PP2` (Алматы, Москвина 23А) — тот
же физический склад, что `Centersna_PP1` (Москвина 23).

В `centersna.xml` всегда ровно один склад `Centersna_PP1` и один город
`750000000`: обкатываем на Алматы, остальные склады в кабинете отключены.
В `matras.xml` склады и города идут как в фиде 1С.

### Остатки в 1С разложены по пяти наборам

Внутри набора склады побайтово одинаковы — физических складов пять, а не
семнадцать:

| Остаток по матрасам | Склады 1С |
|---|---|
| 79 позиций / 257 шт | `PP15` Шымкент, `PP17` Тараз, `PP20` Туркестан |
| 46 / 76 | `PP2` Алматы, Москвина 23А ← источник для Centersna |
| 30 / 67 | `PP21` Актобе, `PP7` Атырау, `PP13` Уральск |
| 29 / 54 | `PP8` Караганда, `PP9` Кокшетау, `PP11` Павлодар, `PP19` Петропавловск, `PP70` Астана, `PP71` Костанай, `PP69` Талгар, `PP67` Конаев, `PP66` Каскелен |
| 22 / 32 | `PP12` Семей |

Если строишь виджет «остатки по городам» — показывай их как пять групп, иначе
дашборд будет врать в пять раз.

## 6. Как цены попадают в файл

```
Таблица цен ──по sku──> живой оффер из фида 1С ──> centersna.xml / matras.xml
     └───по названию+размеру──> архивный оффер Centersna ──┘
```

Колонки таблицы (ищутся по заголовку, порядок не важен):

| Колонка | Обязательна | Смысл |
|---|---|---|
| `sku` | да | артикул 1С |
| любая со словом `kaspi` | да | цена продажи |
| `Товар` | для архива | название, по нему матчим архивные позиции |
| `Продавать` | нет | `нет` → `available="no"` при любом остатке |
| `Магазин` | нет | перебивает разделение по названию |
| `Артикул Centersna` | нет | свой артикул для кабинета Centersna |

Нет строки в таблице — цена остаётся такой, как в фиде 1С. Строка есть, но цена
нечисловая — позиция считается проблемной и цена не меняется.

Разделение по кабинетам: название начинается на «матрас»/«матрац» → Centersna,
всё остальное → 30378397. Колонка `Магазин` перебивает это правило.

## 7. Что не выкладывать на дашборд

Цены и остатки публичны — они и так в XML. **Себестоимость и «Цена 1С» — нет.**
Если дашборд публичный, любая колонка с закупкой утекает конкурентам вместе с
твоей маржой. Считай маржу на бэкенде и показывай процент, а не абсолютную
закупку, либо закрой дашборд авторизацией.

Токены, ключи сервисного аккаунта и куки Kaspi в клиентский код не кладём вообще:
всё, что попало в JS страницы, доступно любому, кто открыл эту страницу.

## 8. Известные дефекты — их полезно показывать

Это то, что дашборд может ловить сам и подсвечивать:

1. **Фид 1С не обновляется.** `Last-Modified` стоит на `31 Aug 2026 08:44`,
   внутри `date="string"` вместо даты. Сравнение снимков за разные дни: ноль
   изменившихся офферов. Виджет «возраст фида 1С» по заголовку `Last-Modified` —
   первое, что стоит сделать: красный, если старше суток.
2. **Клонированные остатки** — см. раздел 5.
3. **Кириллица в storeId**: в фиде встречается `РР70` русскими буквами вместо
   `PP70`. Мы чиним при сборке, но если читаешь фид напрямую — учитывай.
4. **Дубли склада в одном оффере** с разными числами. Берём максимум, не сумму
   и не последнее.
5. **Дробные остатки** в фиде — округляем вниз.
6. **`PP16` и `PP15`** в кабинете — один адрес, Койкелди Батыра 18. Дубль склада.
7. **Талгар, Конаев, Каскелен** привязаны к северной группе остатков вместе с
   Карагандой, хотя это Алматинская область. Похоже на ошибку привязки в 1С.
8. **В кабинете 30378397 все склады отключены** — если это так и осталось,
   `matras.xml` физически не может продаваться.

## 9. Полезные метрики

Считаются из одного файла, без бэкенда:

- возраст данных: `date` из корня XML против `Date.now()`;
- в продаже / всего, деньгами: сумма `цена × остаток` по `available="yes"`;
- позиции без цены из таблицы — расхождение ассортимента с прайсом;
- позиции с артикулом вида `0*` в `centersna.xml` — те самые ~80 с чужим
  артикулом, их Kaspi не примет;
- модели каталога, которых нет в файле, и модели, где все размеры `no`;
- дубли `sku` внутри файла — их быть не должно, это сразу ошибка сборки.

## 10. Если нужен ещё какой-то срез

Логика сборки живёт в `src/merge.mjs`, справочник складов — в `src/stores.mjs`,
разовый прогон с расширенной статистикой:

```bash
node scripts/build-once.mjs out
```

Печатает по каждому кабинету: офферов, в наличии, с ценой из таблицы, снятых,
склад-источник с адресом, сколько артикулов подтянулось из архива.
